# 콘솔 화면 실측 기록 (한국어 UI, 2026-10, 1회 관찰)

구글 콘솔은 자주 바뀐다. 아래는 한국어 UI에서 개인 계정(조직 없음)으로 직접 관찰한 내용이다. 다른 계정 유형, 언어, 시점에서는 다를 수 있다. `확인됨(1회)` 은 한 번 직접 본 것이고, `확인 필요` 는 보지 못한 것이다.

## 메뉴 경로

| 목적 | 관찰한 경로 | 상태 |
|---|---|---|
| OAuth 설정 화면으로 가기 | 상단 탐색 메뉴 > 즐겨 찾는 제품 > API 및 서비스 > OAuth 동의 화면 을 누르면 `Google 인증 플랫폼` 화면으로 이동 | 확인됨(1회) |
| Google 인증 플랫폼 좌측 항목 | 개요, 브랜딩, 대상, 클라이언트, 데이터 액세스, 인증 센터, 설정 | 확인됨(1회) |
| 클라이언트 목록 직접 주소 | `https://console.cloud.google.com/auth/clients?project=<프로젝트ID>` | 확인됨(1회) |
| 테스트 사용자 추가 | 좌측 `대상` 항목에서 한다 (메뉴 이름만 확인, 추가 절차 자체는 확인 필요) | 부분 확인 |
| 범위 설정 | 좌측 `데이터 액세스` 항목 | 확인됨(1회, 조회만) |

### 구 UI 와 신 UI 이름 대응

| 구 UI 이름 (예전 문서에 자주 나옴) | 신 UI(한국어) | 영어 UI 이름 |
|---|---|---|
| OAuth 동의 화면 (앱 이름, 로고) | 브랜딩 | 확인 필요 |
| OAuth 동의 화면 (사용자 유형, 게시 상태, 테스트 사용자) | 대상 | 확인 필요 |
| OAuth 동의 화면 (범위) | 데이터 액세스 | 확인 필요 |
| 사용자 인증 정보 > OAuth 2.0 클라이언트 ID | 클라이언트 | 확인 필요 |

이 표의 "신 UI" 항목은 화면에서 본 이름이고, 구 UI 와의 대응은 화면 구성을 비교해 정리한 것이다. 이전 메뉴(`API 및 서비스 > 사용자 인증 정보`)는 이번에 누르지 않았으므로 지금도 같은 클라이언트를 보여 주는지는 확인 필요.

## 동의 화면 상태 (관찰한 값)

| 항목 | 관찰 값 |
|---|---|
| 사용자 유형 | 외부. `내부로 설정` 은 조직이 없는 계정에서 비활성이었다 |
| 게시 상태 | 테스트 중 |
| 범위 | 이메일 확인 범위 하나. 민감한 범위와 제한된 범위는 `표시할 행이 없습니다` |
| 테스트 사용자 | 1명, 화면의 한도는 100명 |
| 한도 문구 (화면 그대로) | `게시 상태가 '테스트 중'으로 설정된 동안에는 테스트 사용자만 앱에 액세스할 수 있습니다. 앱 인증 전에 허용되는 사용자 한도는 100명이며 앱의 전체 수명 주기에서 계산됩니다.` |
| 개요 화면의 `일일 토큰 부여 10,000회` | 비율 한도이며 만료와 무관하다 |

### 테스트 상태 만료

- 콘솔 화면(개요, 브랜딩, 대상, 클라이언트, 데이터 액세스, 인증 센터, 설정)에는 만료를 설명하는 문구가 없었다.
- 브랜딩 화면의 `테스트 상태` 링크가 연결하는 영문 도움말에 아래 문장이 있었다 (한국어 도움말은 제공되지 않는다고 안내됨). 원문 그대로 인용한다.

  `Authorizations by a test user will expire seven days from the time of consent. If your OAuth client requests an offline access type and receives a refresh token, that token will also expire.`

- 즉 7일 만료는 도움말 문서 기준으로 확인한 것이다. 이번에 만료를 실제로 겪어 보지는 않았다. 세션 로그인만 쓰고 갱신 토큰을 쓰지 않는 앱에서 실제로 어떻게 보이는지는 확인 필요.

## 클라이언트 비밀

- 클라이언트 상세 화면에서 비밀은 `사용 설정됨` 상태로 보이고, 전체 값은 `더 이상 보거나 다운로드할 수 없습니다` 라고 표시된다.
- 따라서 **비밀은 생성 직후 한 번만 안전하게 저장해야 한다.** 놓치면 새 비밀을 만들어야 한다. 새 비밀을 만드는 절차 자체는 확인 필요.
- 클라이언트 목록에는 `마지막 수정` 열이 없고 `생성일` 만 있다. 상세 화면에는 생성 시각과 `마지막 사용일` 이 있다.
- 승인된 JavaScript 원본과 리디렉션 URI 는 상세 화면에서 목록으로 읽을 수 있다 (조회만 하고 저장하지 않으면 변경되지 않는다).

## 프로젝트 생성

- 조직이 없는 개인 계정의 새 프로젝트 화면에는 `프로젝트 할당량이 N개 남았습니다` 경고가 있었다. 조직 정책 제한 문구와 결제 계정 필수 문구는 없었고, 프로젝트 생성에 성공했다.
- 프로젝트 선택기와 리소스 관리 목록에는 **생성일 열이 없다.** 보이는 날짜는 `최종 액세스 날짜` 였다.
- 생성 시각이 필요하면 `gcloud projects list --format="table(name,projectId,createTime)"` 로 조회할 수 있었다 (조회 전용, 1회 관찰).

## 활동 로그로 검증하기 (감사 로그)

프로젝트 활동 로그(Admin Activity)에 다음 이벤트와 시각이 남아 있었다.

`CreateProject`, `CreateBrand`, `CreateClient`, `UpdateBrandWithMask`, `UpdateIcon`

이를 이용해 아래 두 가지를 말이 아니라 기록으로 검증할 수 있다.

1. **내 프로젝트가 정말 오늘 새로 만들어졌는지**: 해당 프로젝트 로그에서 `CreateProject` 의 시각을 본다.
2. **다른 프로젝트가 오늘 변경되지 않았는지**: 다른 프로젝트의 클라이언트 관련 감사 로그를 오늘 날짜로 조회해 결과가 0개인지 본다 (이번 관찰에서는 0개였다).

활동 로그를 여는 정확한 메뉴 경로는 확인 필요. 클라이언트 목록에 `마지막 수정` 열이 없으므로 "수정 여부"는 이 로그로 확인하는 편이 낫다.

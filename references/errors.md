# 구글 OAuth 오류와 해결

일반 지식 기반의 정리다. 정확한 문구는 구글이 바꿀 수 있으므로 공식 문서로 재확인을 권장한다.

| 증상 / 코드 | 흔한 원인 | 해결 |
|---|---|---|
| `redirect_uri_mismatch` (400) | 앱이 보낸 `redirect_uri`가 콘솔의 승인된 URI와 글자 단위로 다름: http/https, www, 포트, 경로 대소문자, 말단 슬래시, 프록시 뒤 스킴 오인 | 오류 화면의 상세 정보에서 앱이 실제로 보낸 URI를 확인하고, 콘솔에 정확히 그 값을 등록. 방금 저장했다면 반영 지연이 있을 수 있다(수 분에서 길게는 수 시간으로 안내됨, 확인 필요) |
| `invalid_client` (401) | 클라이언트 ID 오타, 다른 프로젝트의 ID, 삭제된 클라이언트, Secret 불일치, Secret 앞뒤 공백/개행 | ID/Secret을 다시 확인. 비밀 파일에 개행이나 따옴표가 섞이지 않았는지 확인 (`write_secrets.sh` 사용) |
| `access_denied` | 게시 상태가 테스트인데 로그인 계정이 테스트 사용자에 없음. 또는 사용자가 동의를 거부 | 동의 화면의 테스트 사용자에 계정 추가. 프로덕션 게시는 신중히 |
| `origin_mismatch` | 브라우저 JavaScript 흐름에서 승인된 JavaScript 원본이 등록값과 다름 | 스킴+호스트(+포트)만, 경로와 말단 슬래시 없이 등록 |
| `invalid_request` | 필수 파라미터 누락, 구글 정책 위반(IP 주소 호스트, 운영 http 주소, 공개 최상위 도메인이 아닌 호스트) | 콜백 URI를 https 도메인으로 바꾸고, 라이브러리가 보내는 파라미터 확인 |
| "이 앱은 확인되지 않았습니다" 경고 | 앱 검증을 거치지 않은 상태에서 민감 범위를 요청 | 로그인 용도라면 `openid email profile` 범위만 쓴다. 민감 범위가 꼭 필요하면 앱 검증 절차 필요 |
| 로그인 후 앱에서 "허용되지 않은 계정" | 구글 로그인은 성공했지만 앱 자체의 허용 목록에 없음 | 이는 구글 문제가 아니다. 앱의 허용 목록(환경변수 등) 확인 |
| 로컬은 되는데 운영만 실패 | 운영 도메인의 URI를 등록하지 않음, 환경변수 미주입, 프록시 스킴 | 운영용 URI를 별도 한 줄로 등록하고 배포 환경의 환경변수 확인 |
| 테스트 상태에서 토큰이 만료됨 | 테스트 게시 상태의 갱신 토큰 수명 제한 | `references/publishing-and-scopes.md` 참조 |

## 진단 순서

1. 오류 화면의 코드와 상세 정보를 그대로 읽는다 (코드가 원인을 거의 알려준다).
2. `scripts/check_redirect_uri.sh --lint-only` 로 URI 형식 실수를 걸러낸다.
3. 앱이 실제로 보내는 `redirect_uri` 를 확인한다 (로그, 개발자 도구 네트워크 탭).
4. 콘솔 등록값과 한 글자씩 비교한다. 눈으로 비교하지 말고 복사해서 붙여 넣는다.
5. 저장 후 반영 지연 가능성을 감안해 잠시 후 재시도한다.
